# First 5 Recurring Tables

The 30-day goal: 5 recurring Las Vegas tables actually playing on a standing day and time. Recurring is the bar. A table that plays once does not count. Each table below names a real source, a host candidate from existing relationships, and a backup so no single point of failure stalls it.

Definition of done per table: 4 of 4 seats filled, played at least twice, with a standing day and time and a public meeting place.

## Table 1: Summerlin, current and former students (beginners welcome)

- Target player type: lesson students and recent beginners who want a regular practice game.
- Target location: a Summerlin public spot (library branch or community center).
- Recruitment source: current and former students from the Airtable People table and lesson-leads sheet, plus Summerlin newsletter subscribers.
- Host candidate: Shauna or a strong current student who is ready to host (convert to ambassador).
- Launch plan: invite 6 to 8 students for one weekday afternoon, fill the first table, set it weekly, hand hosting to the student once it is stable.
- Backup plan: if the student host is not ready, Shauna hosts the first month, then transitions. If Summerlin venue falls through, use a Summerlin cafe with table space.

## Table 2: Henderson / Green Valley, open play attendees

- Target player type: experienced players who already attend open play.
- Target location: a Henderson or Green Valley library or senior center.
- Recruitment source: open play attendees in the Attendance table who live in the Henderson area.
- Host candidate: an existing host or organizer from that area (this is the most likely to self-run).
- Launch plan: text the Henderson open-play regulars, pick the day most already play, fill one table, set it recurring immediately after the first game.
- Backup plan: if no local host emerges, recruit a co-host from the same group; if attendance is thin, merge with the Anthem table for the first month.

## Table 3: Anthem / Sun City (active adult community)

- Target player type: active retirees in a 55+ community who play during the day.
- Target location: the community clubhouse or a nearby public room.
- Recruitment source: newsletter subscribers and students in the Anthem and Sun City ZIP codes; the community activities coordinator as a partner.
- Host candidate: a resident organizer (ideal ambassador) inside the community.
- Launch plan: partner with the community activity director to announce a weekly game; seed it with 3 to 4 known players; let the community fill the rest.
- Backup plan: if no resident host, Shauna runs the first two sessions to prove demand, then recruits a resident to take over. Active-adult communities have the highest density, so this table should fill fastest.

## Table 4: Existing host's group (already playing, just formalize)

- Target player type: an existing informal group that already plays but is not on the system.
- Target location: wherever they already meet (move to a public place if needed).
- Recruitment source: existing hosts from the CRM who already convene a game.
- Host candidate: the existing host (convert to ambassador with a referral code).
- Launch plan: the fastest table. Put their current group on the tool, give them the "need a 4th" fill feature, and mark their standing game recurring. Almost zero recruiting.
- Backup plan: if the host is hesitant, offer to manage the reminders for them for the first month. This table should be the first one live.

## Table 5: Newsletter and "I want to play" demand (central Las Vegas / Spring Valley)

- Target player type: scattered players from the email list who have no group yet.
- Target location: a central, easy-to-reach public spot (central library or a Spring Valley community center).
- Recruitment source: the newsletter broadcast replies and any "I want to play" requests, clustered by area on the heat map.
- Host candidate: Shauna to start, then convert the most enthusiastic responder into the host.
- Launch plan: collect area replies from the broadcast, find the densest cluster, invite that cluster to one central table, fill it, set it recurring, promote a regular to host.
- Backup plan: if the cluster is too spread out, split the difference toward whichever neighborhood (Summerlin, Henderson, Anthem) already has a table forming and feed those instead.

## Sequencing and weekly milestones

- Week 1: Table 4 live (existing host group). Start Tables 1 and 2 (students, open play). Send the newsletter broadcast to seed Table 5.
- Week 2: Fill Tables 1 and 2; first games played. Start Table 3 (active-adult community partner).
- Week 3: Tables 1 to 4 recurring; Table 5 forming from broadcast demand.
- Week 4: All 5 filled and recurring (played at least twice). Hand hosting to non-founder hosts wherever possible (see the Founder-Assisted vs Organic dashboard).

## Cross-table guardrails

- Keep a one or two deep waitlist per table from the "I want to play" pool so a dropout does not kill the game.
- Convert at least 3 of the 5 hosts to non-founder hosts within 30 days, or the model is not proven (it just proves Shauna can host).
- Count a table only when it has played twice on its standing schedule. That is the real win.
