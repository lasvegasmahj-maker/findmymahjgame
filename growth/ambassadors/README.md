# Ambassador Growth System

One ambassador, multiple tables, multiple players, recurring games. That is the whole thesis. This folder is the complete system for turning Oh My Mahjong relationships into Founding Ambassadors who launch their cities.

North Star: Tables Formed, then Tables Filled, then Games Played, then Recurring Tables. Not revenue. Every document here exists to move that funnel.

## Read this first (founder)

- [15 Founder Assumptions and Decisions](15-founder-assumptions-and-decisions.md) - the questions only Shauna can answer before we trust the plan: ambassador inventory, the real Las Vegas player pool, the success and failure bar, the expansion trigger, and our moat. Answer these first.

## The goal

Recruit 25 Founding Ambassadors in 25 cities in 30 days. Each ambassador should be able to generate tables, players, teachers, and local awareness, and should be able to launch a city largely on their own.

## How to run this nationally

The motion is one repeatable loop, light enough to run from a phone and not dependent on the founder being in the city:

1. Identify a local leader (warm contact first, then sourced from the playbook).
2. Make the warm ask (recruiting sequence).
3. Approve them and assign a referral code (FMM-{CITY}-{FIRSTNAME}).
4. Onboard to first table within 2 weeks.
5. Hand them the launch kit and city checklist.
6. Help them make a table recurring.
7. Measure on the KPI dashboard, reward what works, repeat in the next set of cities.

Do this for 25 cities in month one, then run the same loop on the next 25 in month two. The system does not change as it scales; only the city list does.

## Operating rules that apply to every document here

- Safety and privacy: new groups meet in public places for the first game; never publish or share home addresses, exact locations, or personal contact information. First names only in shared views.
- Honesty: a table counts only when it exists in the product, not when it is planned. Never turn internal estimates (like the city signal ratings) into public claims.
- Tone: warm, premium, community first, senior friendly. No hype.
- Writing: no em dashes or en dashes; plain ASCII hyphen only for numeric ranges.
